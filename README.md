# amc-hospital-paper

서울아산병원 **병원보 업무 분석 대시보드**.

호(號)별 편집계획안을 읽어 담당자별 업무량, 코너 구성, 부서별 보도량을 봅니다.
제작: 이다예 · 김미소

- 대시보드: https://daye8965.github.io/amc-hospital-paper/
- **처음 넘겨받았다면 [HANDOVER.md](HANDOVER.md) 부터 읽으세요.** 운영에 필요한 내용이 다 있습니다.

## 구조

단일 파일 정적 페이지입니다. `index.html` 하나가 전부이고 빌드 과정이 없습니다.

- 라이브러리: Chart.js, html2canvas, jsPDF (CDN)
- 탭: `current`(진행 현황) / `overview`(전체 현황) / `compare`(연도별 비교) / `staff`(담당자 현황) / `workload`(업무량 분석) / `section`(코너 분석) / `dept`(부서 분석)
- 탭을 추가하면 `nav 버튼` / `tabOrder` / `tabNames` / `<section id="sec-*">` / `show()` 분기를 같은 순서로 맞춰야 합니다

## 데이터

**데이터는 저장소에 없습니다.** 페이지가 열릴 때 Google Apps Script 엔드포인트를 `fetch` 해서
Google Sheets `★병원보 편집계획안(NEW)`(asanpr.members@gmail.com 소유)의 내용을 받아옵니다.

- 탭 하나가 한 호이고, 탭 이름이 호수입니다 (예: `786`)
- 각 탭 상단에 `제786호(12월 1일 자) 콘텐츠 운영 계획`, 그 아래 `지면 | 코너명 | 콘텐츠 | 비고 | 담당` 표
- **실적을 고치려면 저장소가 아니라 시트를 고쳐야 합니다**

### 연도는 호수로 역산합니다

시트에 연도가 없습니다. 병원보가 격주간(1일·15일, 연 24호)이라 호수 하나가 반달이어서,
**786호 = 2026-12-01** 을 기준으로 계산합니다. 날짜가 적힌 98개 호와 전부 일치하며,
날짜가 없는 24개 호도 이걸로 채웁니다. 범위는 668호(2022-01) ~ 789호(2027-01).

기준점(`ANCHOR_ISSUE`)을 바꾸면 **모든 연도가 밀립니다.**

## Apps Script

[apps-script/Code.gs](apps-script/Code.gs) 는 실제로 도는 코드의 **사본**입니다.
여기를 고쳐도 반영되지 않습니다 — 편집기에 붙여넣고 재배포해야 합니다.

- 주소는 `index.html` 의 `GOOGLE_APPS_SCRIPT_URLS` 목록에 있습니다. 위에서부터 시도하므로 **다른 계정의 예비 주소를 둘째 줄에 넣어두면 자동으로 넘어갑니다**
- 재배포: `배포 > 배포 관리 > 연필 > 새 버전` — 이렇게 해야 URL 이 유지됩니다
- `새 배포` 를 누르면 URL 이 바뀌어 `GOOGLE_APPS_SCRIPT_URL` 도 같이 고쳐야 합니다
- 점검: 편집기에서 `testCollect` 실행 (소요 시간·꼭지 수·캐시 상태가 로그에 찍힙니다)

### 속도

탭 122개를 전부 읽으면 40초가 걸리고 웹 앱은 60초에서 끊깁니다.
지나간 호는 바뀌지 않으므로, **최근 4호만 매번 읽고** 나머지는 Drive 캐시 파일
(`amc-hospital-paper-cache.json`)에서 가져옵니다. 새 호가 생기면 그 호만 추가됩니다.

**지나간 호를 고쳤다면** `rebuildCache()` 를 실행하거나 `…/exec?rebuild=1` 을 열어야 반영됩니다.

## 부서 분석에 쓰는 자료

| 파일 | 무엇 | 다시 만드는 법 |
|---|---|---|
| `org-units.json` | 기구조직도(변경) 2026.10.15부의 조직 201곳 | `python tools/extract-org.py "기구 조직도 변경(안).xlsx"` |
| `doctors.json` | amc.seoul.kr 의료진 1,071명 → 대표 진료과 | `python tools/fetch-doctors.py` |

`org-units.json` 은 `index.html` 의 `ORG_UNITS` 에 **붙여넣어** 쓰고(런타임에 읽지 않음),
`doctors.json` 은 페이지가 열릴 때 **읽습니다**.

기사에 부서를 붙이는 세 단계:

1. 제목·비고·코너에 **조직 이름이 그대로** 있는 경우 — 긴 이름부터 보므로 `소화기내과`가 `내과`보다 먼저
2. 비고의 사람 이름이 **의료진 명단**에 있는 경우 — `최영주, 최원묵 (12/8)` → 최원묵 → 소화기내과
3. 1단계로 확정된 기사에서 배운 **직책 붙은 이름**(주임·과장 등) — 부서가 갈리는 이름은 버립니다

확인율은 전체 58%, 2026년 64%입니다. 나머지는 글에 부서 단서가 없거나
독자의 소리·정답 및 당첨자처럼 부서와 무관한 코너입니다.
**부서별 수치는 "확인된 것 중의 분포"이지 전체 분포가 아닙니다.**

## 작업할 때 주의

- 모든 수치는 시트에서 계산합니다. 하드코딩하지 마세요
- `담당` 칸의 공동 담당(`김서영·민경준`)은 **반드시 `staffNames()`** 로 나눠 세세요. 안 그러면 유령 담당자가 생깁니다
- 시트 **머리글이 데이터로 새어 들어옵니다**(옛 호는 열 이름이 `카테고리`). 거르는 조건을 지우지 마세요
- 지면 칸이 **세로 병합**된 곳은 둘째 줄이 빈칸으로 읽혀 `미정`이 됩니다. 병합을 펼치는 코드를 지우지 마세요
- 표는 `.dtable` 클래스를 붙이면 자동으로 정렬됩니다. 글자 순서가 틀어지는 열은 `data-sort` 를 주세요
- 합계·안내 줄에는 `data-nosort="1"` 을 붙여 정렬에서 빼세요
- PDF 출력이 주 용도입니다. 레이아웃을 바꾸면 PDF 결과까지 확인하세요
